# V3.2 八项使用反馈：原因、复现和修复蓝图

日期：2026-10-10。基线：`e3cbe69cddf05b2a424cde0c77149bd9bf4bf456`，分支 `codex/cm-config-runtime-v32-migration-20261007`。

本轮完成代码检查、只读顺序审计及隔离浏览器复现；以下功能修复尚未实施。用户末句要求检查、解释或提供方案，因此先交付完整方案。继续仅本地；不推送、不同步 main/RIA，不改冻结 V1 生产文件。

## 1. 标准面画出后保存提示 CoordG 不足三个坐标

已复现相同错误：生产 MeasuringModule＋NativeWorkflowHost 中，水域工作流实际画出四个顶点，直接点“确认保存输出”，提交数仍为 0，界面提示“已采用 0 个坐标”和“CoordG 第 1 个部件外边界至少需要 3 个坐标”。随后点“采用当前绘制”，计数为 4，保存成功，最终 CoordG 为一部件一外环四坐标。

原因是两份状态没有在保存时衔接：MeasuringModule 有当前地图草稿点，Runner 的 `coordinates[outputId]` 只有按“采用当前绘制”才更新；`submit` 只校验后者，不读取当前有效绘制。V1 NaturalWaterbody/NaturalLand 的 commit 直接从 bridge 取当前点。截图符合未采用的状态，不能据此断言桥接采集总是失效，也不能取消最少三点的几何校验。

修复：标准工作流在绘制页“下一页/确认保存”时读取当前主几何并校验，形成一次本地最终坐标快照，用同一快照做预览求值、record 组装及提交。不能先 setState 再立即读取旧 coordinates。保留显式采用能力，但不把它作为 V1 正常保存路径的额外必经步骤。已采用后继续修改要有脏版本提示，保存用最新对应草稿；多输出、主/辅助点及世界不匹配保持各自边界，不能用最后一个辅助点覆盖主几何。无效捕获保留可修改的草稿，不先清除绘制。

验收：实际 App 画有效面直接保存；不足三点阻断并保留草稿；采用后再改点保存最新；返回上页/撤销重做、主辅点、多输出和切世界。补充旧测试遗漏的“没有点采用就保存”路径。旧 34 次提交脚本都显式点过采用，不能证明该路径正确。

临时使用：先点“采用当前绘制”，看到采用数不少于 3 后保存。

## 2. 字段条件应与 Zoom 一起位于规则头部

确认当前 RenderFieldConditionsEditor 在显示、Label、权重和碰撞设置之后。运行模型已经是同一 `when`，UI 却被分开；这是编辑布局问题。

修复：单一“规则适用范围”头部，第一行必填逻辑 Zoom 0–8，下面选填非分类字段 AND/OR/NOT 条件；之后是显示种类和全部显示内容。新增面板及已有规则统一此布局。仍排除 Class/Kind/SKind/SKind2、存储别名及映射字段，模板内容复制不带源范围条件，模型/优先级不因移动而改变。

## 3. 菱形问号内改为一段易懂说明

当前帮助确实拆成意义/效果/编辑/示例四块，给简单模块增加了阅读负担。

保留菱形问号与 hover/focus/touch、Escape、滚动边界及草稿保护，内容改为模块标题＋一段自然语言，各模块具体写“改什么、会出现什么效果、一般怎么设置”，必要单位和例子合入句子。不能统一拼接四个旧栏目而留下四套重复表达。

例如显示权重：“这里决定同层级要素显示时谁更靠前。一般保留默认；需要按面积、长度或某个字段改变先后顺序时，可选择对应指标，再调整倍率和上下限。它与 Label 的碰撞优先级分别设置。”

验收清单仍覆盖全部扩展子模块、独立碰撞指标及有效值来源。说明仅改善呈现，不改变参数保存路径。

## 4. 共享下拉选项来源的含义

这是配置包的可复用选项表（`registries.optionSets`）。要素字段和工作流 select 可通过同一个来源 ID 引用一份“保存值＋中英文显示文本”列表，避免每个输入各维护一遍。

例如一份选项把保存值 `active` 显示为“启用”，几个下拉框都引用它；修改显示文本后，这些引用处统一显示新名称，已存值仍为 `active`。没有引用该来源、自己定义静态列表的控件不会自动变化。它不是地图数据搜索、分类树或远程自动更新接口；featureSearch 仍走分类限定、多搜索字段/展示模板/单返回字段的独立模型。

此项为解释，不必另造功能。已有来源存在性、默认值/枚举校验继续保留；改保存值时需核对旧记录和默认值。

## 5. 一级 Class 创建、初始空选择和按级分类导航

底层支持创建根 Class。r7 的入口在“读取/新建”已有分类草稿后，“新增要素分类”内勾“作为一级分类”；r6 的主编辑入口主要是添加子类。这种入口不符合直接新建 Class 的使用要求。实际浏览器确认勾选入口存在；它可能位于从 r6 生成的 r7 草稿中，保存版头部仍显示 r6，不能只凭头部推断草稿能力。

另外，selectedId 初值虽为空，selected 又回退 `config.nodes[0]`，effect 还自动选第一项；editorExpanded 初值 false，使验证器默认挂载。主下拉遍历所有 nodes，把具体子分类也混进了首个选择框。

修复：

- 常驻独立“新增 Class”按钮，未选择已有分类也可新建；创建面板有代码、名称、唯一几何、多部件、锚点及兼容模板，不需要假选父级或先读已有分类。
- 初始 Class 为空，验证器关闭且不挂载地图。导入或重新生成后也保持空选择；选择/创建 Class 后才显示相应预览，可主动收起。
- 四级选择：Class 只列一级节点；Kind 只列该 Class 的直接子节点；SKind 只列所选 Kind 的直接子节点；SKind2 只列所选 SKind 的直接子节点。
- 换上级清空下级。可停在父层编辑它的字段/继承规则，不强制落到叶子；未选父级时下级禁用，无子级时明确说明。
- 草稿未保存时继续阻断切换编辑目标；新增根/子节点、保存/放弃、模板复制保留既有原生模型与校验。验证器使用当前实际选定层的有效规则，不混入别的分类。

验收：启动无默认节点/无预览，新建 Class，逐级父范围、清空下级、继承编辑、无子级和草稿保护；不退回 V3.1。

## 6. 工作流框体顺序

对已交付 r7/r3 的 17 个标准 composed 工作流做了逐项审计，全部存在辅助输入顺序丢失。迁移先追加 persisted fields，再追加 auxInputs，最后追加 groups；它们各自已经有 order，但没有跨组保持页面顺序。

受影响范围：

| 分类 | 标准工作流 |
| --- | --- |
| ISG（5） | 陆地、陆面要素、水域、确定聚落范围、规划聚落范围 |
| ISL（4） | 河道、自然边界、确定聚落边界、规划聚落边界 |
| ISP（3） | 特定自然点、人文/地标点、规划/建设点 |
| 其他（5） | 建筑、建筑楼层、道路、传送点、Warp 点 |

冻结 V1 实际组件基础页也已读取：自然要素确实是分类→名称→字符简称→命名者/wiki/简介及其他可选项；BUD/FLR 的分类代号和简称都在可选字段之前。

**不能只修成 schema.sort(order)。** V1 实际页面还有与 schema 不完全一致的布局：道路的功能开关在名称前，三个重复组在限速及可选信息前；TPP 的 wiki 在目标 Warp 前；WRP 是名称→简称→服内 Warp 名。实际组件的完整布局和条件显隐应作为最终参照，并将纠正结果保存为 V3 可编辑 controls 数组顺序，schema 相应修正或明确来源差别。

修复保持既有 control ID、slot、assignment expression 及默认值，不为移位置重新编号 token。已有用户自定义工作流/手排顺序不能一律覆盖；迁移对已识别的标准默认包提供明确差异清单，新默认交付递增包 revision，例如 r4，保留 r3。三种 external 继续执行其 V1 整体组件，不重建为 composed。

验收追加真实 V1/V3 页面顺序、条件显隐及组位置对照，仍跑 34 次完整 record 相等，避免只检查有数据或最终记录相等就宣称操作体验一致。

## 7. 分类选项只显示下辖部分

当前 Runner 的 classificationPicker 先正确按 classificationScope 筛选叶子，再用 workflowPathLabel 拼出完整 Class/Kind/SKind/SKind2；所以长文字是展示问题，不能通过剪切保存值来修。

修复：固定范围 `ISG/NGF/LAD` 时，选项显示 `CON（大陆）`、`ISD（岛屿）` 等直接子码和名称，完整范围在标题/提示中只出现一次。选项 value 仍保留完整分类路径。

范围内还存在多层时，逐级展示当前父节点的直接子级，选到有效最终分类才能继续；不能把相同后缀的不同路径合并，不能因为只想缩短文字就把非叶子当作最终输出。宽范围如建筑仍按 Kind/SKind/... 逐级选择。工作流选择与 Studio 编辑选择可复用路径逻辑，但前者要求最终分类，后者允许编辑父层。

## 8. 标准标签/扩展填写恢复 V1 结构

确认 Runner 对 tagsExtensions 页硬编码两个 JSON textarea，17 个标准工作流又都被附加该页。这并未复现 V1 的填写方式和页面归属；原终端 record 相等测试没填写这些自定义行，未覆盖这里。

V1 已有可复用定义：标签是已注册字段下拉/其他字段名＋按其类型填写值；扩展是组/命名空间、字段名、类型、值。类型为文本、数字、布尔、null。自然工作流的命名者/wiki/简介直接自动填 `tags.nomenclator`、`extensions.link.wiki`、`extensions.character.brief`，并在信息页添加其他扩展。

修复以逐工作流实际 V1 表单为参照，恢复动态行、添加/删除、注册字段、类型与空值/0/false/null 规则；基本信息与可选扩展的页面位置也核对，不能给每个标准工作流强加 V1 没有的 JSON 页。最终仍保存 tags/extensions 对象，不改回 component executor。没有填的命名字段按 V1 处理，已定义的 wiki/brief 等路径与自定义行的重复/优先逻辑逐项对照，不能静默互相覆盖。

标准填写默认不需要 JSON；需要承载已有复杂用户数据时，保留明确的高级查看/编辑入口并保证往返无损，不能只转成简单行就丢失对象/数组。已有字段组和 composed 组装能力继续可编辑，分类/世界保护及危险 target/token 校验继续生效。

验收：真实添加标签/扩展、类型控件、已注册和其他字段、自动映射、重复路径、空值/0/false/null、导入往返，并与 V1 Formatter 最终 record 逐项对照。
