## 1. 可行性结论和 V1/V3 的区别

两项要求可行，推荐一起设计、分主题实施：原生配置在加载/激活时编译成常驻规则模板；编辑模型改为每条规则带必填 Zoom 条件和选填字段条件组，并支持复制完整规则内容。

2026-10-09 用户补充要求已记录：规则字段条件只能使用非分类字段；新增要素分类支持默认继承父级，或从几何和多部件配置相同的分类预填完整显示规则组，同父级平级分类优先。下文纳入该约束；仍为蓝图更新，尚未实施功能。

V1 的树状配置并没有在每帧重新整棵解析。`openriamapRiaClasses.ts` 在模块载入时引入配置；`featureRenderRules.ts` 的模块级 `LEGACY_FEATURE_RENDER_RULES.map(applyConfigDisplayOverlayToRule)` 生成稳定的 `FEATURE_RENDER_RULES` 数组；`renderRules.ts:359` 的 `findFirstRule` 按 Class/Type 取已有对象。动态样式仍按要素和上下文计算，站台点关系/线路选择已有以 FeatureStore 为键的缓存。

V3 当前每次继承查询扫描并排序 95 个节点，重复合成扩展与交互配置；排序、密度预扫描和正式绘制又重复解析要素。默认关闭 hover 仍更新 hoveredUid，触发全轮刷新。此前同应用实验室、相同世界/相机和 463 条数据规模、六次缩放，脚本耗时 V1 0.110s / V3 2.873s，后者有 386–590ms 长任务。该计时来自本机开发环境，不代表其他电脑固定延迟。

因此，用户提出的“进入地图前解析并常驻应用”方向正确。常驻的应是**静态规则模板、索引、受控读取器与依赖描述**；像素位置、碰撞结果、当前字段值及交互结果不能全部冻结在进入地图的那一刻。

## 2. 运行时架构

```mermaid
flowchart LR
  A[可编辑配置树] --> B[加载/保存激活时校验与编译]
  B --> C[常驻分类索引和规则模板]
  C --> E[选择规则并绑定变化的数据]
  D[要素/关联/上下文版本] --> E
  E --> F[按当前视口布局、碰撞与绘制]
```

导出仍保存纯数据；编译结果只在内存中使用。编译是生成索引、规范化数据和绑定已有安全算法，不使用 eval/Function，也不退回 V1 或 component executor。

| 层 | 内容 | 重建/更新条件 |
| --- | --- | --- |
| 配置编译层 | 分类路径及祖先链、字段/显示继承、静态全局覆盖、规则模板、条件读取器、逻辑 Zoom 0–8 的候选规则桶、上下文绑定定义 | 新有效配置快照激活；编辑预览取得新的有效快照 |
| 世界数据层 | 分类/ID/关系索引、每要素几何包围盒、面积/长度/部件数、字段与几何版本 | 当前世界数据加载、临时覆盖/删除/恢复、字段或几何改变 |
| 要素结果层 | 命中规则、字段文本/颜色、关联色、动态指标及相关交互参数 | 声明依赖的字段、关系、Zoom、世界/楼层/选择状态变化 |
| 布局绘制层 | 投影位置、各部件候选、Label 尺寸、碰撞/密度、命中区域、图层样式 | 相机/viewport、字体/图片资源、布局相关参数或状态变化 |

配置缓存按对象身份/运行时 epoch 或内容指纹区分，**不能仅使用 packageId/revision**：同一 r2 草稿可以暂存不同编辑内容。内容指纹只在编译/激活时计算，不在每帧序列化整包。编译结果独立只读，避免修改编辑草稿污染运行版本。

要素缓存还必须覆盖数据/关联索引版本、世界与投影、必要的楼层/交互上下文、资源版本。不同要素实际需要的依赖不同，采用依赖描述决定失效，先以保守失效保证正确性，再缩小更新范围。

不为“全部要素 × 九级 Zoom × 五种状态”预生成全部对象。规则模板共享；要素绑定结果按实际访问缓存，世界卸载时清理，限定缓存规模，避免用内存增长换速度。

### 2.1 一次刷新内的具体流程

1. 使用几何索引取得 padded layoutBounds 内的候选，兼顾 Label 偏移、图片尺寸、跨视口大面和选中/搜索目标；完整数据仍保留给搜索和关联查询。
2. 从分类/几何/Zoom 索引取候选规则，按受控字段条件选择规则。每个要素在同一刷新内只做一次需要的绑定。
3. 预计算几何层级 A、Label 碰撞 B、显示权重 C 和排序键；排序比较器只比较这些数值，不再访问配置树或重复计算面积。
4. 密度、绘制、命中共用该结果。需要符号密度预算的类别才执行相关预算步骤。
5. 当前视口仍执行必要的候选/碰撞/密度布局。已有布局缓存按真实依赖复用，保持 BUD 点/Label、各部件与点击一致。
6. disabled hover 不产生视觉状态更新。开卡记录和视觉状态分离；仅样式改变时更新对应图层，Label 优先级/显隐改变时重排受影响区域，楼层/世界改变时执行需要的较大范围更新。

V3 的显示范围使用原生分类定义与开关语义整理，不能把旧按钮“不影响显示”当作常驻设计，也不能靠隐藏已承诺能力取得性能。视口裁剪须保守，不漏掉几何在外、Label/图标在内的情况。

Web Worker 可作为后续超大数据的编译/几何计算选项；第一步先消除主线程重复工作。Leaflet DOM 绘制及实际文字测量仍需主线程，迁入 Worker 还会增加传输和失效同步成本。

### 2.2 临时挂载兼容

静态配置常驻不冻结地图数据。保留现有 `ria-temp-rule-sources-changed`、`ria-temp-rule-overrides-changed`、`ria-temp-rule-deletes-changed` 协议及按世界隔离的启用、覆盖、删除、恢复语义。数据缓存版本必须包含临时源及覆盖/删除的变化；同 ID 的记录更换字段或几何也必须使绑定、包围盒、各部件 Label、碰撞、命中和信息卡结果失效。继续维护搜索、关联与既有导航索引的更新。挂载变化无需重编译未变的配置模板。

## 3. 新的单条渲染规则

推荐结构（设计示意，不是完整可导入配置）：

```json
{
  "id": "new-rule",
  "when": {
    "zoom": { "min": 6, "max": 8 },
    "fields": {
      "op": "all",
      "items": [
        { "kind": "fieldEquals", "field": "Level", "value": "主干道" },
        { "kind": "fieldPresent", "field": "Name", "present": true }
      ]
    }
  },
  "representation": "geometry",
  "style": {},
  "label": {},
  "geometryStack": {},
  "priority": {},
  "extensions": {}
}
```

匹配逻辑为：`Zoom 范围成立 AND 字段条件组成立`。没有字段组时，字段部分等价 true。

- Zoom 必须显式提供两个整数，`0 ≤ min ≤ max ≤ 8`，闭区间，允许 `8–8`。只有一个 Zoom 范围，不允许用字段组另塞 Zoom 条件。
- 字段条件可选；启用后支持受控的等于/列表/存在与否，以及 all/any/not 组合。UI 默认“全部满足”，允许添加“任一满足”组与否定，不提供任意 JS。
- **字段条件仅允许非分类字段。** 分类路径由所属分类节点及祖先链统一选择；`Class`、`Kind`、`Skind/Skind2`、实际记录别名 `SKind/SKind2` 及指向这些分类字段的映射/别名均不得作为规则字段条件。按规范化字段身份判断，不按显示名称或简单字符串包含判断；普通业务字段、合法 tags/extensions 字段仍可组合。分类兼容映射若将其他旧字段用作分类，也按其真实分类身份排除。
- 非分类限制同时用于字段下拉、复制引用校验、保存/导入校验与编译入口；手写 JSON、嵌套 all/any/not 或别名不能绕过。这里只限制渲染规则的条件区，不禁止工作流正常设置输出分类，也不禁止信息卡显示分类。
- 新版保留现有基本比较语义，明确保存值而非显示文本；检查 false、0、空串、缺失/null 等边界。新数值操作符如需加入，应另行限定字段类型和校验，不能在迁移时悄悄改变比较方式。
- 条件路径来自有效字段及合法 tags/extensions 路径；危险属性路径、无效值和启用后的空条件组阻断保存。建议条件最大深度 4、叶子条件最多 64，作为首版安全/可理解性边界。
- World 继续由引擎维护，新建/迁移规则不自动添加逐条重复 World 条件。

### 3.1 多条命中与权重

**建议按列表顺序，最后命中的完整规则生效。** 编译时每个 Zoom 桶按倒序保存候选，运行时找到第一个匹配即可停止。通用规则放前面，例外放后面，符合旧字段分支后项优先与新增例外通常追加的习惯。

规则选择与 A/B/C 权重独立。不能用显示权重、几何层级或字段数量自动决定哪个配置规则获胜。同一要素正常状态选择一个完整规则，不把多个完整规则隐式混合。

| 顺序 | Zoom | 字段条件 | 完整内容（示例） |
| --- | --- | --- | --- |
| 1 | 6–8 | 无 | 普通道路 |
| 2 | 6–8 | Level = 主干道 | 加宽道路 |
| 3 | 6–8 | Situation = 规划 | 规划道路虚线 |
| 4 | 6–8 | 主干道 AND 规划 | 加宽且虚线 |

同为主干道和规划状态时选第 4 条；没有第 4 条则选第 3 条的完整内容，不自动取得第 2 条的宽度。示例字段值用于说明，实际输入应选择项目的保存值。

允许 Zoom 重叠，因为字段条件及明确顺序决定选择。缺范围、非法范围、唯一 ID 冲突、无效字段和明显矛盾阻断。完全重复匹配条件造成无用规则时阻断；对可证明被后项完全遮蔽的规则定位诊断，复杂交叠给出提示，不承诺穷尽一般布尔条件的可达性分析。

没有命中时沿用包内原生 fallback 定义（隐藏/仅几何），不偷偷调用旧规则。迁移包应保持其原有覆盖与显隐；新增缺口给出诊断。

## 4. 新增与完整内容复制

新增使用独立草稿/创建面板，提供“空白默认”及“从已有规则复制内容”下拉框。

1. 新规则生成新 ID；Zoom 初始待填，字段条件默认关闭。条件有效才加入可激活的规则集。
2. 默认列出当前分类、同一几何类型的本地及继承规则；可扩展到其他同几何分类，但必须进行目标引用校验。选项显示分类、规则名/序号、Zoom/条件摘要，便于识别来源。
3. 深复制 representation、几何/图标/颜色、Label 字段/字体/位置/偏移、A/B/C、全部扩展及继承/覆盖标记。
4. 只排除源规则的匹配 Zoom、字段条件，以及源 ID/编辑身份；选择模板时不覆盖目标已经填写的条件。
5. 不复制运行时函数/缓存或真实要素的绑定值。共享注册表引用仍按正常规则工作，源规则后续编辑不会联动修改副本。
6. 校验复制内容引用的字段、图标、关系、上下文和几何能力；不兼容时定位并阻断保存，不静默改成 Name/ID 或其他效果。
7. 不分割、不缩小、不覆盖原规则的 Zoom。只清除匹配条件；算法内部的 Zoom 桶、切换阈值等仍作为内容保留，不能按名字批量删除。

当前新增逻辑会二分最后一个 Zoom 区间，最后是 `8–8` 等单级区间时直接返回。该逻辑由新的独立新增替代。

### 4.1 新增要素分类时继承或预填完整显示规则组

该功能可使用现有 `CategoryNode`、`inheritDown` 与 `GeometryProfile` 模型实现，不新增一套脱节分类树。创建面板先确定新分类代码/名称、当前父级及目标几何/多部件配置，再提供两种初始化方式：

1. **继承当前父级（默认）**：显示父级经祖先链解析后的有效设置和来源，按现有字段、显示、信息卡各自的向下继承开关生效。未修改时保持继承；修改显示规则组时，将当时的完整有效组复制为本分类本地草稿后编辑，避免修改父级。父级禁止向下继承的内容不得暗中传入；显示该状态，可通过显式选取父级作为兼容模板进行一次性复制。父级未定义几何时，先由用户选择目标类型和多部件设置；无父级的根分类使用系统默认。
2. **从兼容分类预填显示规则组**：可选择配置包内任何有效分类的显示规则组，包括其继承而来的有效组。候选必须与目标几何类型相同，并且 `allowMultipleParts` 相同；多部件开启时，`anchor`（完整要素中心/各部件中心）也必须相同。没有多部件时按规范化的完整中心比较，不让缺省写法造成错误排除。已有父级约束仍须满足，选择模板不能绕过。

选择器依次显示“同父级、同层级的平级分类”“当前父级（兼容时）”“其他兼容分类”，组内按完整分类路径/名称稳定排序；根分类以同为根节点作为平级分组。选项显示完整路径、名称、点/线/面、多部件与锚点、规则数量，支持搜索。几何或多部件选择改变后重新过滤并校验已选模板；不能静默套用失配模板。

复制采用**独立快照**：保留规则顺序、每条匹配 Zoom、合法非分类字段条件，以及 representation、style、Label、几何层级、显示权重、完整扩展和规则交互视觉覆盖。该功能复制一整组可用显示规则，因此与“新增单条规则”不同，**不清空源规则的 Zoom 和字段条件**。生成新的 nodeId 和全部规则 ID；后续编辑源分类不联动副本。保留规则内显式的继承/覆盖意图；全局默认的继承仍指向当前包的引擎默认，不把全局值固化成重复本地设置。

新分类代码、路径、名称和父子关系由本次创建输入决定；字段定义、信息卡、工作流、分类/上下文关系不从模板分类一并复制，继续按目标父级及现有开关解析。目标几何、多部件、锚点与几何级交互触发保持创建面板确定的设置，不被源规则组暗中改写。

跨分类模板可能引用目标尚未具备的字段、图标或关联上下文。载入草稿时列出具体引用及问题路径，允许用户调整目标字段或替换引用；未修正前不能保存/激活，不静默删除条件、补成 Name/ID、复制源分类身份或改变工作流输出分类。取消创建或放弃草稿不留下半成品节点；切标签继续执行未保存草稿阻断。

## 5. 版本与旧包迁移的关键疑虑

规则形态和匹配语义改变，建议契约升级为 **contractRevision 7**，产品仍为 V3.2；新包保存 revision 单独递增，例如 r3。r5/r6 原包、历史与交付 r2 保留，不覆写。

当前 r2 只有 3 条规则带 conditionalOverrides，最多 2 个分支，均为 direction/Connect 的等于或列表条件，其中两个 direction 分支互斥。它们可用基础规则加完整例外规则等价转换。

任意用户旧包却不能只拆成“基础 + 每个分支”：旧逻辑允许 A 改线样式、B 改 Label，A/B 同时命中时组合两者；新完整规则必须明确增加 A+B 内容。转换器需要按**原有合成语义**产生必要组合并剪除可证明不可能的组合，再按后项优先排列，附来源映射与差异清单。

分支多时可能产生组合增长。建议每个源规则自动生成最多 64 条转换规则，作为待审阅上限；超过或无法证明等价时不生成有损 r7，不强制替换有效旧包。旧 r6 可继续由优化后的原生编译内核运行，待隔离转换草稿处理完成后再启用新模型。

旧包还可能带嵌套 Zoom/面积条件。嵌套 Zoom 可与父区间求交；面积条件不能被假装成普通字段或直接丢弃，须保留原生兼容语义并在转换报告中定位。当前 r2 没有这类旧分支，但必须纳入自定义旧包迁移测试。

旧包若有分类字段条件，不能直接照搬到新 r7 字段条件组，也不能直接删除以伪造等价。仅在可证明与所属分类路径等价或冲突时做相应规范化/诊断；其余保持原有效 r6 包并生成隔离迁移问题，待明确调整分类归属后再启用 r7。

缓存失效、规则重叠和累积覆盖转换是本方案真正的风险点。编译器必须声明依赖、保留原始包与可审计来源；不能把“常驻”解释为不再响应修改，也不能把不改变渲染作为性能成功。

## 6. 实施顺序和配套范围

| 顺序 | 独立主题 | 核验要点 |
| --- | --- | --- |
| 1 | 保留当前源码/性能证据，补实际实验室冷启动模块入口 | 公共启用弹窗、加载/失败反馈；测绘/测量在桌面与窄屏真实可用 |
| 2 | r6 原生常驻编译内核、索引与依赖缓存 | 冷编译/热复用与旧解释结果逐项相等 |
| 3 | 渲染刷新复用、预计算键、裁剪与交互增量 | disabled hover 无视觉刷新；选中/楼层变化仍正确布局；实际长任务下降 |
| 4 | r7 多条件模型、明确匹配选择和无损迁移 | 重叠、AND/OR/NOT、边界、旧同时命中组合与回退正确 |
| 5 | 新增规则/分类、模板复制及统一编辑器 | 单条规则条件独立；分类整组保留条件；几何/多部件兼容、平级优先、合法引用、继承与草稿一致 |
| 6 | 先前配套 UI 要求 | 高级模块收进扩展；密度编号与实际降级顺序一致；菱形问号帮助 |
| 7 | 全量回归与本地交付 | 默认显示及最终 record 不变；版本/导入/激活正确；人工验收状态明确 |

先前提出的模块入口、扩展收纳、密度顺序与模块帮助继续保留，未因本次讨论取消。字段条件分支编辑器被单规则条件区替代；“有效扩展值与来源”不在本轮另行提出改造。

每个功能主题单独本地提交，并执行 `npm run verify:config-v32` 和 `npm run build`。不推送上游/下游，不改 main，不 reset 原工作树。

## 7. 验收目标

- 逻辑 0–8、包含 `0–0/8–8`，同字段组合、空/false/0、多个命中、无命中、规则排序、完全遮蔽与复制后编辑均有正负例。
- 分类字段及其记录别名/映射在直接条件和嵌套组合中均被阻断；非分类业务字段与普通 tags/extensions 路径正常使用，手写 JSON 和导入不能绕过。
- 新分类父级默认继承、关闭继承、首次本地编辑、兼容模板和平级优先排序；点/线/面及多部件/锚点不匹配的负例；整组复制保留 Zoom/非分类条件及顺序、独立 ID、源修改不联动、引用失配阻断、取消/放弃与切标签阻断。
- 旧 r5/r6 多分支同时命中、面积条件、导入失败保持原有效版本，以及新 r7 JSON/ZIP 往返与真实激活。
- 冷编译和热命中、字段/几何/关系/世界/楼层/字体/图标/配置变化逐项验证失效；不保留过时颜色、文字、锚点或点击区域。
- 实际测绘入口执行挂载、启用/停用、字段/几何修改、同 ID 覆盖、删除、恢复及世界切换；显示、字段条件选择、信息卡/点击、搜索/关联和现有导航索引同步。
- 保持独立 V1 的 909+252 显示场景、密集场景、真 BUD 点、九方向、SVG、各部件与英文空值；保持 34 次标准工作流最终记录及 7 条 external 输出对照。
- 性能以实际 Lab 与同数据/相机/构建方式的 V1 作比较。463 条基准场景热运行目标：六次缩放脚本耗时不超过 V1 两倍；控件/开卡反馈 P95 目标 ≤100ms；disabled hover 不触发配置树遍历或全世界重排。另设放大数据/密集标签场景，不能只用四个可见 Label 证明大场景可用。
- 上述数字为**待实施后实测的目标**，不是已达成承诺。记录编译启动时间、CPU、长任务、布局、缓存命中与内存；不能仅凭 build 或画面截图标记性能通过。

最终交付为原生可编辑配置与编译内核、迁移/匹配语义报告、性能与正确性证据；用户人工验收与首次转正另行记录。
