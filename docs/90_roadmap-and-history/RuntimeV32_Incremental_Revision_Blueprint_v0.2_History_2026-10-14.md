## 2. DRAW-01：自动绘制与实时反馈

### 2.1 用户操作

1. 进入已启用且配置为自动启动的绘制页，自动切换到对应点/线/面任务，恢复该任务已有草稿；无需点击“进入绘制”。
2. 普通自动绘制状态不常驻“进入绘制”和“采用当前绘制”按钮，也不把手动采纳作为下一页或保存的前置条件。
3. 坐标数量与几何有效状态随地图实际草稿更新；取消“已采用 N 个坐标”对旧快照的依赖，显示当前任务的真实绘制状态。多部件/孔环按该任务的完整几何反馈，不遗漏已完成部件。
4. 下一页和保存可用状态同步反映当前几何是否具备最低有效条件：点至少 1 个坐标，线至少 2 个，面外边界至少 3 个有效顶点；继续满足既有多部件、孔环、输入和输出校验要求。撤销到无效状态后及时更新反馈。
5. 下一页、任务切换及最终提交自动采集对应任务的最新有效数据；提交时再次读取当前活动任务的实际地图草稿，不能只使用最近一次按钮采纳的快照。
6. 保留必要的“添加部件/添加孔环”等实际能力。明确配置不自动启用、显式暂停或世界不匹配后需要恢复的场景，可以使用有明确原因的启动/恢复入口；不将其作为普通流程的固定步骤。

### 2.2 实现约束

- 使用绘制桥接的实际状态通知更新反馈，避免高频轮询、重复解析配置或全图刷新。
- 保留提交阶段完整校验、世界守卫及防重复保存。按钮可用反馈不能替代最终校验。
- 同一几何内容只维护明确的任务归属和必要快照，不增加需要用户理解的第二套“采用”状态。
- 无真实地图桥接的工作台模拟预览，保留明确标识的样例几何/预览坐标能力，不与真实测绘的按钮和坐标反馈混淆。

## 3. DRAW-02：最后绘制任务持续开启

### 3.1 状态语义

“仅保留最后一个”针对活动绘制任务，不表示删除其他绘制页的坐标草稿。

1. 每个绘制任务分别保存草稿，主几何与额外绘制的任务键、返回槽位、输出字段绑定保持独立。
2. 任意时刻仅一个任务接收地图绘制操作；切换任务前保存旧任务最新坐标，随后恢复新任务草稿并设置其绘制类型。
3. 从绘制页进入普通信息页时，继续维持最后离开的绘制页对应任务。填写信息期间仍可在地图上修改该任务的几何。
4. 在多个普通信息页之间前进或回退，不因页面类型改变而暂停、清空或转移活动任务。
5. 再进入绘制页时，按该页任务决定是否切换。若仍是同一活动任务，不用旧快照覆盖在信息页期间新增、删除、拖动、撤销或重做的坐标。
6. 切换到不同任务时，必须采集实际活动任务的最新草稿，即使离开的页面是信息页；不能只在“上一页是 geometry”时保存坐标。

### 3.2 用户指定的 TPP 必须行为

前置：TPP 的 F 为空，额外目标点绘制启用。

| 操作 | 活动绘制任务 | 草稿与输出归属 |
| --- | --- | --- |
| 在主几何绘制页绘制起点 | TPP 主几何点 | 保存为主几何任务草稿 |
| 进入目标点绘制页并绘制目标点 | 额外目标点 | 保存主几何草稿，目标点独立写入自身任务 |
| 从目标点页回退到主几何页 | TPP 主几何点 | 保存目标点草稿，恢复主几何草稿并自动开启主几何绘制 |
| 再回退到基本信息页 | TPP 主几何点，保持开启 | 目标点草稿保留，地图操作仅修改主几何 |
| 在信息页修改主几何，再进入主几何页 | TPP 主几何点，继续开启 | 保留信息页期间的最新修改，不回滚到进入信息页之前 |
| 再进入目标点页 | 额外目标点 | 保存主几何最新结果，恢复目标点草稿 |
| 最终保存 | 提交完成后退出绘制 | CoordP 与 TGTcoordinate/TGTelevation 等分别取正确任务结果，不串用坐标或高度 |

额外点继续保留此前已确认的标准 CoordP 与 `{x,y,z}` 返回格式选择，TPP 当前目标点按其 pointObject 配置输出；此次不更改坐标契约或组装语义。

### 3.3 必须兼容的边界

- 额外绘制的启用条件失效时，停止失效任务的活动绘制，并清除其有效预览/槽位输出；失效任务不得因“保留最后任务”继续接收地图操作或参与提交。可保留的内部草稿不等于可输出的有效数据。
- TPP 从 F 为空改为使用 Warp 引用后，额外目标点不再参加绘制输出；不将旧目标坐标误作为当前有效结果。
- 世界不匹配、显式停止/放弃任务、取消/退出工作流、成功提交之后，不继续绘制。本规则不绕过现有世界守卫和退出清理。
- 既有 `allowBack`、`keepDrawingWhenBack` 和 `enabledFromThisPage` 的显式设置需逐项核对；本条针对允许保留绘制的正常流程，不擅自覆盖配置明确要求的禁止返回、清除草稿或非自动启动行为。
- 点/线/面、多部件、孔环、坐标高度、撤销/重做、临时挂载及原生采集/编辑共用桥接的行为均应保持正确。外部成品工作流不因通用桥接调整而改变其既有状态机。

### 7.3 按实际容器宽度换行

- 使用容器宽度决定列数；可采用 container query 或 `repeat(auto-fit, minmax(min(100%, 适当最小宽度), 1fr))`。不能仅凭屏幕达到 sm/md 就在较窄弹窗里强制三列。
- 代码、名称 zh、名称 en 的 label 和 input 均 `min-width:0`、`width:100%`、`max-width:100%`，输入在容器内收缩；低于合理可操作宽度时依次降为两列/一列，不互相覆盖。
- 几何、多部件开关、显示模式、四个同步开关、模板选择采用相同换列规则。长标题自然折行，不让输入挤出容器。
- 普通输入、select 和布尔按钮保持统一正常高度，使用 `align-items:start`、`align-self:start` 等避免相邻长内容拉伸；textarea 只扩大自身。
- 小屏动作区自动换行，错误报告可读且不覆盖按键。长 ID/URL/字段名采用 `overflow-wrap:anywhere`；单行输入可以在自身内部滚动，不使整页溢出。
- 以 320/390/600/900/1440px 视口、不同实际弹窗宽度及浏览器 125%/150% 缩放验收；不限制为只支持截图所在屏幕大小。

## 8. FORM-01～04：采集、编辑和长表单修复

### 8.1 是否按钮

- 无论整行、半行或三分之一行，容器占满所在控件宽度，两按钮各占 50%，分界线始终在中间。
- 支持未选 / true / false 三态：点“是”写 true，再点已选“是”清除；点“否”写 false，再点已选“否”清除；点另一侧直接切换。
- 清除写未设置值，不写相反值，也不将 false 当作空值。必填字段取消后显示必填错误并阻断推进；可选字段按原有默认值/省略策略组装。显式取消不得立即在界面悄悄重新选中。
- 使用默认值的语义与“用户明确选择”区分；组内新行没有声明默认值时不自动把 toggle 初始化成 false。保持 Oneway 必选、Enter/Exit 等既有缺省语义与最终记录对照。
- 同样覆盖重复组内、绘制页信息槽位与标准再编辑；键盘操作与 aria 状态一致。

### 8.2 信息页头尾双导航

- 除默认填写人页与绘制页外，每个普通信息表页在标题/世界/页数下方与页面末尾各放一套上一页/下一页结构。
- 两套导航调用同一组动作、校验、禁用状态及防重复操作逻辑；若当前为最后信息页，尾部现有最终动作与顶部对应动作保持一致，不额外制造不同提交路径。
- 切页后将该页内容滚动到标题区域；头尾操作都不能丢输入、跳过必填、重复保存或改变当前活动绘制任务。
- 保留 DRAW-02：从绘制页回信息页仍可绘制；从信息页点击顶部下一页重新进入绘制时，仍须归档最新实际几何，不能恢复旧快照。

### 8.3 搜索与重复组

- 搜索控件区分正在输入的 query、已选记录/展示文本和最终返回值，单独管理联想框展开状态。
- 选中候选后立即关闭联想框，停止把完整展示模板当查询；不会弹出“无匹配要素”。点击外部、Escape、失焦也正确收起；重新输入才重新检索。
- 编辑回填时恢复已选值与展示文本，不依赖用户重新搜索。用户更改 query 后旧结果不能仍作为有效选择；保留原单返回字段、多搜索字段、显示文本与保存值分离的语义。
- 候选 ID、Name、返回值报告均完整折行；结果列表宽度受控，只在自身内部纵向滚动。必要时以两行分别展示 ID 与名称，禁止把 ID 尾部裁切为不可查看。
- 重复组列使用最小宽度与顶端对齐，左侧连接方式 select 保持正常高度和标题下的位置；右侧搜索展开、提示/报告增高不会拉伸左侧。
- 项标识使用稳定 ID，增加/删除/排序不能将上一项的 query 或已选结果串到另一项。同时覆盖对象数组与纯值数组。

### 8.4 标签与扩展的空态

- 新采集时两组均为零行，仅显示组标题与“添加标签行/添加扩展行”按钮；点击添加第一个条目后才出现字段、类型和值输入。
- 删除最后一行回到零行，不自动补一个空编辑行。固定 tags/extensions 控件本身仍不可删除、可以移动，仍在第一页信息收集末尾，不重新拆成独立页面。
- 编辑已有记录时按已有数据回填；该要求不清空已有标签或扩展。自动填写项保持原来源和冲突校验。
- 关闭“高级对象查看与编辑（保留复杂数据）”的原始对象修改入口，不向用户提供可误写整个对象的 textarea。已有复杂数据原样保留；如确需显示，可放只读且默认收起的查看区，不包含编辑操作。
- 关闭入口也不得丢失无法由简单行完整表示的对象/数组。保存仅对用户明确修改的结构化路径增量写入，保留其余值，维持 0/false/null 与类型。

## 9. REL-01：通用包含关系身份

位置：要素设计中渲染规则区之下、搜索控制之下。该设置归属于字段设计模块，与字段设计同步、继承、模板复制和分类导入导出一起处理，不再是固定分类对的独立关系编辑器。

### 9.1 界面与定义

1. “启用包含关系绑定”开关。
2. 开启后选择自身身份：“主结构”或“附属结构”。
3. 主结构：可选“指向附属单元字段”，从当前分类有效字段选择。空置合法，主要关系依然通过附属引用主结构的 ID 建立；此字段用于 BUD/STB 等既有正向附属列表的兼容。
4. 附属结构：必填“指向主单元字段”和“附属结构层级切换字段”，均从当前分类有效字段选择。例如 FLR 使用 BuildingID / NofFloor；STF 使用当前真实对应字段，不擅自统一改写既有数据名。
5. 不选择限定目标分类。任一声明为附属的分类均能挂靠任一声明为主结构的分类，例如 FLR→BUD 与 FLR→STB 同时可用。

### 9.2 运行和迁移

- 以当前世界中的记录 ID 建立角色索引，分类只决定其角色与自身字段路径，不限定对方 Class。主结构可兼有多个附属分类；层级选择从真实附属记录构成，不能只读取第一组绑定。
- 附属→主结构为主要关系。主→附属的可选字段仅补充旧数据：同一关系去重；反向字段与附属明确主引用相冲突时报告，不能把附属同时分派到两个主结构。
- 切换层级、进入/保持视角、候选/点击/碰撞及楼层筛选继续使用共享上下文算法；通用 Zoom/激活半径等仍在全局引擎，不重复塞进每个分类。
- 不存在字段、字段形状不适合 ID/层级、角色冲突或相同世界 ID 解析歧义阻断配置/数据核验；不存在目标记录作为数据问题报告，不能错误挂靠同名或其他世界记录。
- 迁移默认 BUD/STB 为主结构，FLR/STF 为附属；完整迁移原 contextBindings 意图及已有主向下引用兼容。不能仅删除老编辑器而保留运行时的分类对限制。
- 模板复制后同步改写被重命名字段；若父级硬继承规定了角色与字段，外部模板只在其之上增量合并，不覆盖硬继承。缺少依赖字段则在创建/导入时阻断。

## 10. SEARCH-01：分类搜索控制

位置：渲染规则区之后、包含关系绑定之前。存入字段设计所属配置，随字段设计继承与同步。与工作流的专用 SearchProfile 区分，不使用同一个名字掩盖不同职责。

### 10.1 搜索资格与来源字段

- “可被搜索”开关控制主页、导航等通用搜索结果。默认迁移当前 V1 搜索资格，PFB 等原禁搜项保持原状态。
- 搜索来源为当前有效字段多选区，Name、ID 固定必选；可以添加 tags/extensions 的具体路径等其他字段。固定项不能被清除。
- 通用搜索使用共享编译索引，并保持现有世界过滤、排序和临时挂载更新。不开启通用搜索不会删除数据，也不切断 ID 关系查找或按自身配置运行的工作流专用搜索。

### 10.2 搜索副标题

搜索结果保留四个位置：主名称、下方灰色小字、副标题右侧延伸区、右侧灰色坐标。主名称与坐标沿用当前行为；本轮编辑后两项。

- 副标题模式：“显示分类”“显示分类+（本要素字段）”“显示本要素字段”。分类名仅取该要素实际所属的最深具体分类名称，不拼接完整上级路径。
- 后两种模式选择一个本分类有效字段，再选解释方式：
  - “显示值”：直接显示该字段实际值，保留 0/false；空值不显示 undefined/null 字样。
  - “显示值对照意义”：提供既有预填入口，复制字段值→zh/en 意义对照。选择该模式时必须有可用的双语对照；缺少 zh 或 en、重复保存值、不覆盖声明的可选值等报错。英文不从中文兜底，不能为通过核验而自动编造翻译。
  - “显示值连接外部字段”：本字段值视作目标记录 ID；目标展示字段直接填写文本路径，默认 Name，不要求先选某个目标分类，也不提供限定某个分类字段的下拉框。
- 外部查找使用当前世界的共享记录索引；允许跨 Class，不额外 fetch 每条结果。目标缺失、歧义或读取不到指定路径给出可定位诊断，不错误显示其他目标。
- 示例：FLR 选择“显示分类+（本要素字段）”，字段 BuildingID，解释为外部字段，目标路径 Name；得到“默认（抹岚1号公寓）”一类副标题，主名称仍为该房间名。

### 10.3 延伸区域

- “延伸区域显示模式”选项为“无”“名称+颜色胶囊”“关联线路胶囊”。后两者复用信息卡对应显示器的可编辑参数与实际解析，不重建第二套含义不同的设置。
- 关联线路保留原搜索的小型胶囊、布尔可用性过滤、重复线路分段合一、颜色及稳定次序；迁移时对照现有 bureau/line/名称前缀等合并键，不简单按不同线段 ID 逐条输出。
- 搜索与信息卡同时修改如下选项文案，存储值与效果保持原样：

| 原文案 | 新文案 | 保留存储值 |
| --- | --- | --- |
| 当前平台 | 当前站台(向下一层关联) | platform |
| 当前车站 | 当前站场(向下二层关联) | station |
| 当前车站建筑 | 当前车站建筑(向下三层关联) | stationBuilding |

- 默认搜索副标题、楼层所属建筑、铁路三层胶囊按当前 V1 行为迁入可配置状态；迁移前后逐类结果对照。现有特殊分类显示名称用可编辑数据保留，不继续仅留在 TS 专用分支。

## 11. PREFILL-01 / INHERIT-01：清除、变化提醒与硬继承

### 11.1 三种复用机制明确分开

| 机制 | 用户入口 | 更新语义 |
| --- | --- | --- |
| 分类树硬继承 | 字段/信息卡向下继承设置 | 上游有效定义更新后同步到继承范围，子级不能用本地同名副本遮挡硬继承 |
| 一次性预填 | 每个模块的“预填” | 注入当前有效定义和已解析对照快照，之后可自行修改；源变化只提醒，不自动覆盖 |
| 既有表格绑定 | 明确点击“使用既有表格”并选择表格 | 保存明确 tableId，持续读取该表；需要独立修改时解除绑定并转为自填副本 |

最新要求增加的是明确的表格绑定，不恢复此前删掉的无具体用途的共享 Direction 下拉区，也不让普通预填偷偷变成活动来源跟随。

### 11.2 清除与过期警告

- 所有“本地显示对照 N 项；需要更新时重新预填。”后增加“清除”，包括信息卡及本轮同类副标题/显示映射模块，不只改一个固定文本实例。
- 清除移除本模块的本地对照及其预填核验摘要，恢复初始无对照状态，不删除实际要素值、字段设计、名称或其他格式设置。仅依赖对照的 enum 格式同步恢复为原值显示；其他独立格式不受影响。
- 硬继承项不能在子级用清除绕开父定义；明确表格绑定的项清除/解除必须有准确语义与可见状态，不能表面为 0 项但仍在读旧表。
- 字段定义/名称/类型/字典改变时，沿有效字段继承链计算影响范围。该分类、其祖先变更所影响的后代分类中，同字段的独立卡片项/本地搜索对照，以及工作流下拉控件/重复组字段的快照需要检查。
- 最后核验产生 warning：指出来源分类、字段、变更内容、受影响模块和重新预填入口，提示用户确认是否需要刷新。字段不存在、类型不兼容、未知表格、非法输出等真实错误仍按 error 阻断，不降级为警告。
