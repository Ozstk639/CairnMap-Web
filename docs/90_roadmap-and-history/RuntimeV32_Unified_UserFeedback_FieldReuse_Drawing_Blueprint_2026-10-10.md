## 2. 标准面绘制后直接保存：采集最新有效草稿

来源：A「1. 标准面画出后保存提示 CoordG 不足三个坐标」。除子标题编号统一外，以下条款保持原文内容。

已复现相同错误：生产 MeasuringModule＋NativeWorkflowHost 中，水域工作流实际画出四个顶点，直接点“确认保存输出”，提交数仍为 0，界面提示“已采用 0 个坐标”和“CoordG 第 1 个部件外边界至少需要 3 个坐标”。随后点“采用当前绘制”，计数为 4，保存成功，最终 CoordG 为一部件一外环四坐标。

原因是两份状态没有在保存时衔接：MeasuringModule 有当前地图草稿点，Runner 的 `coordinates[outputId]` 只有按“采用当前绘制”才更新；`submit` 只校验后者，不读取当前有效绘制。V1 NaturalWaterbody/NaturalLand 的 commit 直接从 bridge 取当前点。截图符合未采用的状态，不能据此断言桥接采集总是失效，也不能取消最少三点的几何校验。

修复：标准工作流在绘制页“下一页/确认保存”时读取当前主几何并校验，形成一次本地最终坐标快照，用同一快照做预览求值、record 组装及提交。不能先 setState 再立即读取旧 coordinates。保留显式采用能力，但不把它作为 V1 正常保存路径的额外必经步骤。已采用后继续修改要有脏版本提示，保存用最新对应草稿；多输出、主/辅助点及世界不匹配保持各自边界，不能用最后一个辅助点覆盖主几何。无效捕获保留可修改的草稿，不先清除绘制。

验收：实际 App 画有效面直接保存；不足三点阻断并保留草稿；采用后再改点保存最新；返回上页/撤销重做、主辅点、多输出和切世界。补充旧测试遗漏的“没有点采用就保存”路径。旧 34 次提交脚本都显式点过采用，不能证明该路径正确。

临时使用：先点“采用当前绘制”，看到采用数不少于 3 后保存。

- 枚举/下拉输入：对照表同时提供允许选项和显示映射。
- 普通文本、数字或布尔字段：可以只有显示对照，不因添加对照行就自动变成只能从列表选择的枚举。wiki、命名者仍可自由填写。
- 保存值按字段约定的值类型解析并校验，显示文本始终为文本；明确区分 `0`、false、空字符串、null 与未填写，不靠真假值判断。
- 为既有 enum 保留原本存储值语义。若需要数字/布尔枚举，字段需声明对应存储值类型，不能未经声明将 `"1"` 和 `1` 混用。
- 重复保存值、无效类型、默认值不在必需枚举范围、多值/单值不匹配均阻止保存。
- 继承字段显示实际来源；修改继承内容仍需“建立覆盖”，不偷偷改父级。

复用仍通过分类树上的字段完成：例如在某 Class 定义命名者/wiki，子分类继承；其他 Class 的工作流可搜索并导入该字段。此轮不另建一个新的全局公共字段注册表。

### 8.2 删除共享选项入口与原生依赖

删除 Config Studio 的“共享下拉选项来源”，以及字段“选项注册表”、工作流“共享选项来源 ID”编辑入口。新规范中原生字段和输入直接持有或跟随字段内的对照表。

旧包导入时先迁移，不能直接删 `optionSets` 导致原选项丢失：

1. 找出全部来源引用，并把实际有效选项落入对应字段/控件；继承消费者按有效定义处理，避免不必要的重复本地覆盖。
2. 同时有静态选项和来源时，以旧版本实际执行语义为准，并输出差异；不任意拼接两个列表。
3. 空或缺失来源单列诊断，不能生成一个假装可用的空枚举。
4. Direction 空注册表移除。RLE `direction` 字段合法编码依据已核对的铁路协议整理进字段内；外部铁路工作流仍按其明确的协议运行，不声称修改字段表会自动改外部组件。
5. 导出新版本不再携带旧全局来源；旧结构只在导入迁移边界识别，原生运行器、编译缓存和预检不再依赖它。

已存在的用户包和 r3 交付包留存，不覆盖原文件或同版本包。

## 9. 信息卡自动跟随字段定义及手动覆写

来源：B「3. 信息卡默认跟随字段，允许明确覆写」。除子标题编号统一外，以下条款保持原文内容。

用户在信息卡选择某个字段后，默认显示该分类下的有效字段定义：标题读取字段 labels；值读取字段对照表。不存在对照项的值保持原值展示，不造一个错误名称。

UI 显示“跟随字段定义”，提供分开的“覆写显示名称”和“覆写值对照”开关。覆写项才持有本地值，关闭覆写后恢复跟随；不能通过字段是否为空暗中猜测是否覆写。

- 继承字段与分类本地覆盖按当前实际记录分类解析，主地图卡片和工作台预览相同。

## 10. 输入模块内部搜索导入、来源追踪及冲突预检

来源：B「4. 工作流输入模块内部的搜索并导入」。除子标题编号统一外，以下条款保持原文内容。

### 10.1 入口和导入范围

每个普通输入模块及重复组子字段的设置区提供“搜索并导入”。移除表单外的 `WorkflowFieldBindingEditor` 和“按字段定义添加输入，并绑定到输出……”整块入口。

导入面板流程：搜索分类代码/名称与字段名/名称 → 按 Class/Kind/SKind/SKind2 逐级限定 → 选择有效字段 → 查看将导入的内容和差异 → 应用。

结果包含字段所在分类、继承来源、真实路径、类型和值数量，不能只列一堆无出处字段名。

默认导入：标题 zh/en、输入控件、默认值、提示、格式、选项和值对照、可转换的必填设置、归一化约定、引用搜索配置。类型和值数量决定是否需要文本/数字/下拉/搜索/重复组。

字段基于 record 的条件与工作流基于 slot 的条件不是同一语言：只有依赖字段已明确绑定为当前工作流的可用槽位，才能转换条件；否则提示缺少依赖并要求补齐，不能机械复制一个不可执行的字符串。

导入只改变当前模块。既有 control ID 和 slot 保持稳定；不因更改标题/类型重新编号表达式 token。需要从单值变重复组时显示转换差异，不抹掉已有组行。

“同时绑定到输出”作为明确选项：目标输出存在兼容字段时预填路径；若来源属于其他分类或当前输出已绑定同字段，则提示选择目标/复用现有绑定。导入配置不应暗中制造第二条同目标写入。

### 10.2 跟随与覆写，不能只有一次性拷贝

推荐默认“导入后跟随字段定义，可逐项覆写”，同时保留“转为独立配置”。导入记录源分类节点、字段稳定 ID、有效字段路径、导入快照/指纹与本地覆写项。

- 未覆写的标题、翻译、提示等安全变化跟随来源；修改工作流某项后，该项明确变为本地覆写。
- 可查看来源、差异，执行重新导入、恢复某项跟随或转为独立。
- 转为独立必须先确认实际目标字段仍允许当前输入/输出，不能用断开来源规避目标字段校验。
- 不通过字段名称文本寻找来源；名称可改，稳定 ID 与分类身份维持引用。
- 继承路径发生本地覆盖时重新解析实际有效定义，并显示来源变化。

预检阻断真实冲突：源字段已删或不再有效、字段/控件类型和基数不兼容、选项或默认值失效、字段引用搜索失效、输出 target 失效、必填条件无法满足、覆写产生不符合目标字段定义的输出。

显示名称、说明、翻译变化，或仍合法的用户覆写，不应一律当作冲突。诊断必须定位到“分类 → 字段 → 工作流/信息卡 → 模块”，并提供具体修复入口。

仅靠保存导入快照不能满足上述要求，需在统一预检中维护消费关系。Studio 草稿、导入、保存、导出、Config Lab 激活使用同一校验；运行中已开始的工作流继续使用其配置快照，避免用户填到一半因配置更新突然变形。

合并保留 A 第 4 项中未被替换的搜索约束：featureSearch 继续采用分类限定、多搜索字段、独立展示模板和单返回字段；字段内选项对照不替代数据搜索。原选项来源存在性检查迁入旧包导入校验，新字段/控件仍执行默认值、枚举范围及既有数据核对。

## 13. 通用条件绘制、额外点线面及点坐标返回格式

来源：B「7. 统一绘制任务，支持启动条件与额外几何」。除子标题编号统一外，以下条款保持原文内容。

### 13.1 两种可添加任务

| 任务 | 编辑内容 | 结果 |
| --- | --- | --- |
| 输出要素 | 标题、设置条件、输出分类、点/线/面、字段组装 | 条件成立时产生独立 feature record，并参加挂载/导出 |
| 额外绘制 | 标题、设置条件、点/线/面、几何 slot、所属输出与目标字段、存储转换 | 条件成立时采集几何并写入已有输出字段；不另造分类/feature |

“设置条件”放在每个绘制标题下面、分类/目标字段上面的一行，可展开编辑。提供此前已定义槽位的选择与“为空/有值/等于”判断；必要的组合条件使用相同的受控模型。无需条件时默认执行。

额外绘制不能只扩展当前辅助点标题：模型需支持线/面的真实多部件几何；捕获、草稿、预览、几何校验和提交一起修改。每个绘制任务独立稳定 ID 和草稿，不复用一个最后活动的坐标变量。

### 13.2 条件运行与预检

- 条件只能依赖此前可用的信息槽位或此前已完成的绘制结果，不能依赖自身、后续槽位或形成循环。
- 0、false 为有效值；F 为空是“没有有效选中 Warp”，不是搜索框是否还留有输入文字。
- 运行时跳过未启用任务，页序号随实际任务变化；返回修改前页后重新计算。
- 条件失效的旧采集值保留为可恢复草稿，但不参与本次有效 slots、预览、组装、几何必填或提交；再启用时重校验。主、辅助以及各输出不会互相覆盖。
- 条件输出只提交当前启用的输出集合。现有 `prepareNativeWorkflowCommit` 的“结果数量必须等于全部 outputs”检查必须改为验证活动输出集合与身份，不能简单删掉数量检查。
- 活动输出依赖被跳过输出的 ID/分类/几何时阻断，并定位依赖。至少需要一个实际可提交输出。
- 对条件必需的辅助绘制，启用时未画有效几何必须阻断；未启用时不能再要求必填。
- 保存时采集当前对应绘制的最新有效草稿，并使用同一不可变快照完成校验与组装；与上一批“画完直接保存报错”修复使用同一条路径。
- 切世界仍保留现有隔离与回原世界继续的保护。

### 13.3 返回坐标格式选择与 TPP 兼容

额外绘制内部使用当前规范采集几何；当绘制格式选择“点”时，在该模块中提供“返回坐标格式”下拉框，直接选择：

| 返回坐标格式 | 写入槽位及目标字段的结果 | 点数量 |
| --- | --- | --- |
| 标准 CoordP 数组（默认） | `[[x,y,z], ...]` | 按采集配置允许一个或多个点 |
| 单点坐标对象 | `{x,y,z}` | 仅一个点 |

选择对象模式时限制为单点采集，并对导入或残留的多点草稿阻断校验；不能静默截取首点或末点。两种返回格式使用相同的坐标轴、高度规则和几何校验，仅改变额外绘制结果的序列化形状。

线、面继续使用规范数组，不扁平化部件：

- 线：与 CoordL 一致的 `[[[x,y,z], ...], ...]`。
- 面：与 CoordG 一致的“部件 → 环 → 坐标”数组。

绑定目标需要是真正可容纳所选返回结构的字段（例如相应 JSON/数组或坐标对象字段），预检检查返回格式与目标结构是否匹配。切换格式时保留几何草稿、重新校验绑定，不静默改写目标字段。主 CoordP/L/G 仍由输出几何系统按标准规范写入；该选择器只用于额外绘制，不能借辅助输入随意覆盖主几何。

- 链接、日期、关系跳转、颜色胶囊、数组/对象等格式继续保留。对照映射作用于可显示值，不能破坏链接目标、关系 ID 或复杂对象的结构。
- 字段删除、字段类型不兼容、引用失效、手动枚举覆写产生无效存储值等阻止应用配置。单纯改标题或翻译不构成冲突。
- 既有卡片迁移先保持 V1 当前可见效果：已有标题/格式与有效定义不同的项保存为明确覆写；相同的项可转为跟随。不能因为引入自动映射就批量改掉旧卡片显示。

“显示名称”需要区分字段标题与字段值的名称，预览同时展示真实值和对照后的文字。

## 4. 工作流输入模块内部的搜索并导入

### 4.1 入口和导入范围

每个普通输入模块及重复组子字段的设置区提供“搜索并导入”。移除表单外的 `WorkflowFieldBindingEditor` 和“按字段定义添加输入，并绑定到输出……”整块入口。

导入面板流程：搜索分类代码/名称与字段名/名称 → 按 Class/Kind/SKind/SKind2 逐级限定 → 选择有效字段 → 查看将导入的内容和差异 → 应用。

结果包含字段所在分类、继承来源、真实路径、类型和值数量，不能只列一堆无出处字段名。

默认导入：标题 zh/en、输入控件、默认值、提示、格式、选项和值对照、可转换的必填设置、归一化约定、引用搜索配置。类型和值数量决定是否需要文本/数字/下拉/搜索/重复组。

字段基于 record 的条件与工作流基于 slot 的条件不是同一语言：只有依赖字段已明确绑定为当前工作流的可用槽位，才能转换条件；否则提示缺少依赖并要求补齐，不能机械复制一个不可执行的字符串。

导入只改变当前模块。既有 control ID 和 slot 保持稳定；不因更改标题/类型重新编号表达式 token。需要从单值变重复组时显示转换差异，不抹掉已有组行。

“同时绑定到输出”作为明确选项：目标输出存在兼容字段时预填路径；若来源属于其他分类或当前输出已绑定同字段，则提示选择目标/复用现有绑定。导入配置不应暗中制造第二条同目标写入。

### 4.2 跟随与覆写，不能只有一次性拷贝

推荐默认“导入后跟随字段定义，可逐项覆写”，同时保留“转为独立配置”。导入记录源分类节点、字段稳定 ID、有效字段路径、导入快照/指纹与本地覆写项。

- 未覆写的标题、翻译、提示等安全变化跟随来源；修改工作流某项后，该项明确变为本地覆写。
- 可查看来源、差异，执行重新导入、恢复某项跟随或转为独立。
- 转为独立必须先确认实际目标字段仍允许当前输入/输出，不能用断开来源规避目标字段校验。
- 不通过字段名称文本寻找来源；名称可改，稳定 ID 与分类身份维持引用。
- 继承路径发生本地覆盖时重新解析实际有效定义，并显示来源变化。

预检阻断真实冲突：源字段已删或不再有效、字段/控件类型和基数不兼容、选项或默认值失效、字段引用搜索失效、输出 target 失效、必填条件无法满足、覆写产生不符合目标字段定义的输出。

显示名称、说明、翻译变化，或仍合法的用户覆写，不应一律当作冲突。诊断必须定位到“分类 → 字段 → 工作流/信息卡 → 模块”，并提供具体修复入口。

仅靠保存导入快照不能满足上述要求，需在统一预检中维护消费关系。Studio 草稿、导入、保存、导出、Config Lab 激活使用同一校验；运行中已开始的工作流继续使用其配置快照，避免用户填到一半因配置更新突然变形。

## 7. 统一绘制任务，支持启动条件与额外几何

### 7.1 两种可添加任务

| 任务 | 编辑内容 | 结果 |
| --- | --- | --- |
| 输出要素 | 标题、设置条件、输出分类、点/线/面、字段组装 | 条件成立时产生独立 feature record，并参加挂载/导出 |
| 额外绘制 | 标题、设置条件、点/线/面、几何 slot、所属输出与目标字段、存储转换 | 条件成立时采集几何并写入已有输出字段；不另造分类/feature |

“设置条件”放在每个绘制标题下面、分类/目标字段上面的一行，可展开编辑。提供此前已定义槽位的选择与“为空/有值/等于”判断；必要的组合条件使用相同的受控模型。无需条件时默认执行。

额外绘制不能只扩展当前辅助点标题：模型需支持线/面的真实多部件几何；捕获、草稿、预览、几何校验和提交一起修改。每个绘制任务独立稳定 ID 和草稿，不复用一个最后活动的坐标变量。

### 7.2 条件运行与预检

- 条件只能依赖此前可用的信息槽位或此前已完成的绘制结果，不能依赖自身、后续槽位或形成循环。
- 0、false 为有效值；F 为空是“没有有效选中 Warp”，不是搜索框是否还留有输入文字。
- 运行时跳过未启用任务，页序号随实际任务变化；返回修改前页后重新计算。
- 条件失效的旧采集值保留为可恢复草稿，但不参与本次有效 slots、预览、组装、几何必填或提交；再启用时重校验。主、辅助以及各输出不会互相覆盖。
- 条件输出只提交当前启用的输出集合。现有 `prepareNativeWorkflowCommit` 的“结果数量必须等于全部 outputs”检查必须改为验证活动输出集合与身份，不能简单删掉数量检查。
- 活动输出依赖被跳过输出的 ID/分类/几何时阻断，并定位依赖。至少需要一个实际可提交输出。
- 对条件必需的辅助绘制，启用时未画有效几何必须阻断；未启用时不能再要求必填。
- 保存时采集当前对应绘制的最新有效草稿，并使用同一不可变快照完成校验与组装；与上一批“画完直接保存报错”修复使用同一条路径。
- 切世界仍保留现有隔离与回原世界继续的保护。

### 7.3 返回坐标格式选择与 TPP 兼容

额外绘制内部使用当前规范采集几何；当绘制格式选择“点”时，在该模块中提供“返回坐标格式”下拉框，直接选择：

| 返回坐标格式 | 写入槽位及目标字段的结果 | 点数量 |
| --- | --- | --- |
| 标准 CoordP 数组（默认） | `[[x,y,z], ...]` | 按采集配置允许一个或多个点 |
| 单点坐标对象 | `{x,y,z}` | 仅一个点 |

选择对象模式时限制为单点采集，并对导入或残留的多点草稿阻断校验；不能静默截取首点或末点。两种返回格式使用相同的坐标轴、高度规则和几何校验，仅改变额外绘制结果的序列化形状。

线、面继续使用规范数组，不扁平化部件：

- 线：与 CoordL 一致的 `[[[x,y,z], ...], ...]`。
- 面：与 CoordG 一致的“部件 → 环 → 坐标”数组。

绑定目标需要是真正可容纳所选返回结构的字段（例如相应 JSON/数组或坐标对象字段），预检检查返回格式与目标结构是否匹配。切换格式时保留几何草稿、重新校验绑定，不静默改写目标字段。主 CoordP/L/G 仍由输出几何系统按标准规范写入；该选择器只用于额外绘制，不能借辅助输入随意覆盖主几何。

当前 V1/V3 的 TPP 目标坐标字段是 `{x,y,z}`，另有 TGTelevation。因此额外绘制直接选择“单点坐标对象”即可兼容 TGTcoordinate，无需用户另外配置数组到对象的转换函数或逐轴组装表达式。

推荐配置：

1. 主绘制：起点，点类型，始终启用，产生 TPP 的 CoordP。
2. 额外绘制：目标点，点类型，启动条件 `F 为空`；“返回坐标格式”选择“单点坐标对象”，目标字段选择 `TGTcoordinate`。
3. 按所选格式直接写入坐标对象；高度优先取实际采集 y，其次手填高度，坐标对象缺省 y 按现有 -64 规则；TGTelevation 的省略/空值语义仍与 V1 一致，不能把缺省 -64 无条件写入所有高度字段。原始采集高度是否存在与序列化缺省值分开保留，避免误判为实际输入高度。
4. F 有值时跳过目标绘制，只输出 TGTWarp，排除此前目标几何/高度残值。

这样编辑界面不再暴露一堆 TPP 专用辅助点轴槽与同目标覆盖行；通用转换由返回格式选择器内部完成，实际结果可直接预览。字段绑定继续可编辑，普通使用不需要额外打开表达式构造器配置转换。

验收补充：同一点以两种格式返回时坐标值相同；对象模式多点阻断；格式切换后目标结构不匹配阻断；0/负坐标及高度缺省正确；导入导出保留所选格式；TPP 两条分支最终 record 与 V1 保持一致。

删除旧 TPP 专用 UI/旧辅助点结构应在新模型迁移和两条分支 record 对照通过之后进行。SOURCE_POINT 等旧槽、旧 assignment 的导入转换要留出明确路径，不能先删旧语义再补数据。

远端当前 6 条 TPP 都有 TGTWarp，没有 TGTcoordinate 分支样本，因此该分支必须使用冻结 V1 实际组件/Formatter 和专门 fixture 验证，不能用远端审计结果声称它已经覆盖。
