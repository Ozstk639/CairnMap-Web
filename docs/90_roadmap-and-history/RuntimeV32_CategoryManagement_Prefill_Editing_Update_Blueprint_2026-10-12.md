## 1. 逐项核验结论与必须明确的边界

各项需求均可实现，但以下四点属于实施设计的一部分，不能只调整界面：

1. 分类几何能力与渲染内容目前在同一个 GeometryProfile 中；四项同步开关要求拆开职责。未选择同步显示时，应保持真正空白，不能悄悄回退显示父级规则。
2. 当前 validateProfile 对空渲染规则报错。要使纯空白分类在创建时完全合法，需要增加“尚未配置显示”的显式状态；它可保存但暂不渲染。启用显示后，仍必须拥有有效规则。
3. AND/OR 是二元关系，NOT 是一元否定。行头下拉和总公式必须映射到同一布尔语法树，不能把 NOT 当作连接两项的第三种二元关系。
4. 工作流四项条件是准入前置条件。还须实际尝试生成编辑投影与记录回填方案；拼接或计算表达式通常不能自动反解。转换测试失败就不启用，不靠猜测回灌。

对“导入后用上游固定字段覆盖”的执行解释：遵循用户同时规定的父级固定继承优先，使用上游有效定义修正导入文件的冲突项，不反向修改父级本身。不同于创建模板时的同名字段重命名，此处涉及固定字段，不能用改名绕过它的强制约束。

## 3. 将 r8/r4 装入应用默认配置，统一版本选择

### 3.1 当前原因

ConfigStudio 和 ConfigLab 的无历史状态工厂已经生成 r8/r4，但 Studio 优先读取 sessionStorage 的 saved/draft；Lab 优先恢复会话草稿，再读 IndexedDB latest。因而以前的 r2 可以持续抢占默认。Lab 当前上传只更新当前 state 与 IndexedDB，并未统一清理旧会话恢复指针，刷新还有恢复旧会话的可能。

### 3.2 默认配置与活动配置

1. 使用已验证的 r8/r4 JSON 作为随应用发布的默认种子，绑定 manifest、契约、包版本和内容摘要；不再每次打开页面先从旧 r2 重建整树。
2. 默认种子与用户保存版本分开；Studio 与 Lab 使用同一个活动配置读取器、版本选择记录及迁移流程。上传、保存、切换版本、返回实验室都更新同一活动指针。
3. 用户未明确选择旧版本时，旧的 latest/session r2 不再仅凭历史存在自动胜出。对可证明是旧默认包且没有用户修改的 r2，存入历史后自动将活动版本改为默认 r4，迁移只执行一次。
4. 不能仅根据 packageId/revision 判定“无修改默认包”。对自定义旧包或未保存草稿先保留完整恢复副本，并提供可见的“默认 r4 / 恢复旧内容”状态；使用默认 r4 不需要再次上传。不得悄悄丢掉或改写未保存编辑。
5. 用户后续上传、保存或主动选择的有效版本成为持久活动版本，刷新保留它；提供“恢复应用默认配置”入口，默认种子不覆盖后续用户选择。
6. 正常刷新不自动进入编辑态，也不自动选择 Class；普通正式主地图仍按现有 V1 边界运行。本轮默认更新针对 V3 工作台及实验室，不等于 V3 转正。
7. 默认 JSON 首次加载、预检、编译一次；同进程共享不可变编译结果。避免为 ZIP 解压或反复校验造成缩放/点击刷新开销；默认资源不能塞进每次渲染循环。

先以原始 r8/r4 建立可验证默认安装；本轮新数据模型交付时，生成递增的契约/包版本（建议 r9/r5），并把应用默认指针升级到其迁移后的配置。原 r8/r4 ZIP/JSON、版本身份和摘要保持不变，不能把新结构继续冒充 r8/r4。

验收：有旧默认 r2 的同一浏览器直接刷新得到 r4；空浏览器首次进入得到 r4；上传及显式切换后刷新不回 r2；自定义旧包和未保存草稿可恢复；反复进入无重复迁移；Studio/Lab 当前版本一致。

## 5. 分类草稿生成：强制继承优先，增量复制与完整预检

### 5.1 四个同步开关的语义

本面板的“同步”指创建时复制/初始化各模块，不建立对外部模板的持续引用。祖先明确声明的固定向下继承、系统 World/分类身份等约束，独立于这些可选开关并始终生效。

区分父级向下传递控制、字段固定/可覆盖/localOnly、此次创建的可选复制，不能用同一个勾选值承担三种含义。现有 inheritDown 的传递意义保持；接收方的可选显示/卡片继承需要独立表达，以免空白区又被运行时自动补回。

| 开关 | 来源与落地内容 | 未勾选时 |
| --- | --- | --- |
| 同步字段设计 | 来源实际有效字段、名称、类型、值数量、字典及数据约束 | 不复制可选字段，仍保留目标祖先强制字段/系统字段 |
| 同步几何设置 | 几何类型、多部件能力、部件显示模式及必需几何能力 | 使用三项手动设置，遵守祖先硬约束 |
| 同步显示渲染设置 | 全部 Zoom、字段公式、顺序、样式、Label、扩展及交互显示配置 | 不复制可选规则，明确未配置显示；不隐式使用模板/父级显示 |
| 同步信息卡设置 | 完整卡片项、区域、关系/链接、格式等局部显示配置 | 不复制可选卡片；明确空卡片，保留最低系统行为 |

几何交互能力与规则内的交互视觉覆盖按职责分别归属；同步几何不能顺带把整组渲染规则复制过来。

### 5.2 字段增量合并与重命名

1. 先解析目标祖先所有有效强制字段和系统约束，形成基底，不改变父级。
2. 根据所选模式/开关取得来源有效字段，逐项增量加入基底。
3. 同名路径且语义定义、名称、值内容、格式、数量、约束等完全一致时跳过，视为基底已提供。内部 fieldId、生成时间等身份差异不算语义差异；字段值类型与实际内容必须逐项相同。
4. 同名但定义或内容任一不同时，生成唯一后缀 _1、_2……；tags/extensions 只改末段键，保留命名空间。代码/系统字段和不可改的固定身份不能靠后缀绕过；无法合法重命名就阻断。
5. 重命名同时重写此次一起复制的渲染公式、Label/颜色来源、信息卡 source/nameSource/colorSource、关系来源及相关数据约束。不能只改字段列表，留下悬空依赖。
6. 生成新的内部 node/field/rule/card ID，并重建所有内部引用；输出分类路径按目标位置建立，不复制来源分类身份和来源 children。来源下游传递策略按可适用约束保留，不复制无关外部绑定身份。
7. 创建报告展示强制继承、复制、跳过一致项、重命名与引用调整，能够追溯每一处决策。

### 5.3 创建按键与合法性

- 仅在点击“创建分类草稿”时开始完整解析、组装和预检；按钮旁显示处理中、结果和阻断原因。
- 在隔离候选配置中检查路径连续、同级代码重复、内部 ID 唯一、几何/多部件/锚点、字段类型、公式依赖、颜色映射、卡片关系和外部资源。
- 仅复制外部渲染而缺少其依赖字段，或只复制卡片但关系字段不存在，都阻断。报告指出具体模块/字段和修复选择，不自动勾选更多同步项。
- 声明在字段组内的自定义 tags/extensions 路径可以引用；未声明的路径不能作为绕过模板缺失字段预检的通道。已有迁移兼容读取与新创建的严格依赖检查分开。
- 未同步显示时，生成明确“尚未配置显示”的合法状态，无活动显示规则、无暗中默认图案。配置树合法保存，主图暂不画此分类；用户启用显示后必须补齐至少一条合法规则。未同步卡片生成合法空白卡片。
- 世界等最低系统约束由引擎提供；纯空白不等于移除系统字段、固定继承、不可删除 tags/extensions 组。
- 全部阻断项清零后才把候选安装为新分类草稿；失败不插入半成品、不改变选择、不修改已保存总包。
- 成功后退出新增参数填写态，选中新草稿供字段/几何/渲染/卡片编辑。未保存仍受草稿阻断保护；核验与保存完成后，才成为可正常再次读取的分类。

## 6. 恢复分类导入及两级事务管理

### 6.1 文件类型、输出与通用流程

- 保留整包上传/下载功能，但与分类导入按钮清楚分开。
- 在分类管理工具条恢复“导入分类”；只接受本模块导出的“单一具体分类”或“Class 从属完整分类树”信封格式，可为 JSON 或带 manifest 的 ZIP。
- 导出选择“当前具体分类”或“当前 Class 从属树”；后者必须包含该 Class 根与全部后代，前者只含所选节点，不顺带导出 children 的内容。
- 信封明确 kind、版本、目标分类路径、必要祖先/外部依赖、内容摘要、节点及相关配置；严检文件类型、摘要、契约与路径。不得把任意总包猜成单分类文件。
- 单分类导出保留可移植的本地配置、继承约束及所需依赖说明，不把未导出的祖先复制成“独立根”。只导出已核验版本，不能把无效草稿输出成有效导入件。
- 输出不包含要素数据、全局引擎的任意覆盖、无关工作流或其他 Class 内容。卡片、关系、扩展所需外部引用显式列出；独立导入时检验目标总包能提供它们。

### 6.2 单一具体分类导入

1. 解包、检查节点与祖先链，再对比目标总包；不自动补建缺少的 Class/Kind/Skind/Skind2。
2. 上级 Class 缺失时按用户要求提示：“不存在上级Class，请选择导入整体分类树或逐级上传保存”；中间祖先缺失时进一步指出缺少的实际层级/路径，并要求整体树或逐级保存。
3. 导入 Class 根的单节点文件不需要祖先；已有同路径 Class 时进入替换草稿流程。
4. 检查与上游固定字段及内部 ID 的冲突。使用应用现有风格的阻断弹窗，展示逐项冲突与最终调整预览。
5. “按上游约束修正后继续”使用上游固定定义覆盖导入冲突项；取消则不导入。必须同时修正受影响引用并重跑校验，不能确认一下就绕过验证。
6. 内部 ID 与别的分类碰撞可进行一致重映射，显示报告；同分类路径替换需要明确差异预览，不把分类代码自动改名。无法安全调整的 ID/外部引用冲突始终阻断。
7. 导入只形成所选节点隔离草稿，经过读取/核验/保存流程注入总包；放弃不影响原分类。不能修改上游本体来迁就导入文件。

### 6.3 Class 从属分类树导入模式

完整 Class 树导入后，分类管理区包入一个“Class 树导入总控”容器：

    总控：导入 Class、节点数量、差异、状态、核验 / 保存到总配置 / 放弃导入
      内部：编辑分类四级选择 / 新增分类 / 读取 / 核验 / 保存 / 放弃草稿 / 导出

- Class 选择固定为导入根，不能添加另一个 Class。目标选择和新建位置仅能位于该树；内部仍保留第 4–5 节相同结构与三种初始化方式。
- 其他分类模板如需使用，可只读查询当前总包的其他 Class，不允许通过来源选择修改外部 Class，也不改变目标根。
- 读取与编辑基于暂存树；所有祖先均在树内，并检验连续、children 引用、唯一性及固定继承。外部依赖检验使用“总包 + 暂存树”的隔离合并视图，不能误判合法跨 Class 关系不存在。
- 内部“保存”只把当前节点草稿写入暂存树；内部“放弃草稿”只撤销当前节点草稿；内部导出仍支持单节点/当前 Class 全树。
- 总控“核验”检查整树及其向总包注入后的全部受影响配置；存在未结束的内部草稿时，先要求内部保存/放弃，不允许静默漏掉编辑。
- 总控“保存到总配置”必须核验通过并一次性注入；检测导入前后总包被其他编辑改变的情况，再核验差异，不使用过期基线覆盖。
- 总控“放弃导入”整体撤销暂存树，恢复导入前状态；有内部草稿也通过同一弹窗明确整体撤销。
- 只有总控保存成功或总控放弃，才退出该模式。内部保存/放弃不能提前回普通编辑界面。总控不另设导出按钮。
- 失败保持完整暂存树可继续修复，无半树写入已保存包；会话恢复保留暂存树和内部草稿层级。

### 6.4 状态与预览隔离

分为已保存总包、暂存 Class 树、当前节点草稿三层。一般编辑只有总包和节点草稿两层。每层的按钮必须说明作用范围。显示规则验证器只预览当前隔离配置，不激活主地图；总控未保存时 Lab 和其他模块仍用已保存总包。

## 7. 字段组合条件：条件行与总公式统一

### 7.1 界面

- 继续位于渲染规则头部，与必填逻辑 Zoom 0–8 同一“生效范围”模块。
- 条件行采用用户指定顺序：关系下拉 AND/OR/NOT → 稳定条件编号 → 非分类字段下拉 → 比较关系下拉 → 值输入 → 删除/排序手柄。
- 字段只能是当前有效非分类字段；Class/Kind/Skind/Skind2 及其实际别名、间接指向分类的定义仍禁止。
- 存在/为空比较不显示值框；枚举显示保存值和 zh/en 名称，数字、布尔采用对应控件，避免 0/false 被当空。
- 简单关系默认根据行顺序生成公式，不需另写表达式。AND/OR 为连接符；NOT 否定本行，简单列表中默认以 AND 接入，界面明确显示 AND NOT。首行 AND 为起始项，首行 NOT 为否定起始项，不产生隐形左操作数。
- 提供“组合公式”输入和插入 AND/OR/NOT/括号/条件编号按钮，可组合多组条件；每个命名组可折叠，仍对应同一公式。
- 如需 OR NOT、否定整组或更复杂关系，通过公式/分组入口显式表达，不能让 NOT 下拉具有含糊的隐式二元语义。

### 7.2 求值、编辑与校验

例如只接受 C1，且 C2/C3 不成立：

    C1 AND NOT C2 AND NOT C3

三项中恰好任意一项成立：

    (C1 AND NOT C2 AND NOT C3)
    OR (NOT C1 AND C2 AND NOT C3)
    OR (NOT C1 AND NOT C2 AND C3)

- AND/OR/NOT、括号、条件/组编号为受控布尔语法；NOT > AND > OR，括号可改变优先级；不接受 JavaScript、不使用 eval。
- 行定义和公式只有一份规范模型，公式编译成 AST。手动自定义公式后，不能再在行排序时暗中重写它；仅调整编号的显示位置，稳定 ID 保持，依赖删除时给出可修复错误。
- 比较保留等于、属于、存在，增加其明确否定；数值比较按字段类型限制。复杂对象/数组不允许假装标量比较，需显式适用操作。
- 括号缺失、未知条件、循环组引用、空组合、非法字段/值、非法 NOT、可证明矛盾均阻断。不能保证证明所有任意公式矛盾；不宣称完整布尔定理求解。
- 放宽当前最多四层的 UI 嵌套限制；提供足以覆盖实际复杂规则的解析预算，建议 256 个原子条件、32 层、16 KiB 公式文本，并给出清楚超限提示。
- 加入真实记录条件结果预览/真假表。主地图、验证器、碰撞、点击共用编译后的同一条件求值，不再每次缩放重复解析。
- 旧 all/any/not AST 转为等价公式，原规则顺序/重叠规则处理不变；迁移以完整记录匹配集合相等验证。

## 9. 所有跨模块字段调用改为一次性“预填”

### 9.1 统一入口与注入语义

每个工作流信息收集控件、组内字段、绘制页额外输入，以及每个信息卡显示单元的准备填入区，都提供“预填”按钮。按钮打开一致的搜索窗口：分类四级选择、字段搜索、实际有效字段、数据路径/名称/类型/数量/格式/值字典预览。

点击导入：

1. 读取用户选择的具体分类下的实际有效字段，包括合法继承和本地覆盖。
2. 按消费模块映射字段名/路径、名称 zh/en、类型和值数量、建议控件/格式、值对照；不复制来源分类身份。
3. 来源明确提供的属性覆盖当前同类属性，包括明确空的 en 和明确的空字典；来源未提供的属性保留当前值，但与新类型/数量不兼容的内容必须调整或阻断，不能残留旧下拉/无效默认值。
4. 展示本次实际变化；导入是一个可撤销的草稿操作，不立刻保存整个模块。
5. 不留下 nodeId/fieldId/来源快照/覆写列表/自动跟随状态，不在运行时回读来源定义。再次预填即再次读取当前来源信息并注入。

名称或字典修改以后，其他模块不自动变化；有需要由用户再次预填。预检仍检查真实数据字段、控件保存值类型、基数、选项、输出绑定、关系目标、表达式等实际配置合法性，不因一次性来源改名/消失本身阻断。不以“没有来源关系”等于“无需数据契约校验”。

### 9.2 工作流

- 导入字段名成为控件的本地保存字段信息/建议绑定目标；内部稳定 control ID/slot 保持，不能为了改标签重新编号而破坏表达式。
- 按字段类型/值数量创建或调整文字、数字、下拉、布尔、JSON、重复组等控件，保留 select 显示文本与保存值分离。
- 继续提供“同时绑定到输出”，只允许有效兼容输出；字段被占用则编辑原绑定或报告冲突，不创建重复赋值。
- 搜索的分类、多搜索字段、展示模板、单返回字段由控件本地拥有；结构性字段引用可在预填时给出建议，导入后仍是独立可编辑设置。
- 输入的默认值、提示、执行条件、归一化属于控件本身。本轮纯净字段不再保管输入默认值/提示，预填不从已移除的字段属性偷取这些信息。
- 已有输入布局、说明、合法默认值、执行条件，以及其他非注入属性保留；新字段不能使其无效。保护 systemManaged 固定模块与 output 分类绑定。

### 9.3 信息卡

- 预填注入 source 字段路径、名称 zh/en、显示格式及枚举对照的局部副本；保留显示器、区域、颜色、关系设置等非冲突内容，用户可继续修改名称和格式。
- 删除跟随/覆写开关、恢复跟随状态和“信息卡手动覆写对照”编辑入口。字典通过预填更新，信息卡不设第二个修正基础字典的编辑器。
- 为保持一次性语义，卡片显示所需的字典副本仍可存为本地显示数据；它不是活动来源引用，也不是一个可在卡片侧任意手工改写的对照表入口。
- 数组逐值映射、未命中保存值原样展示、空英文保持空、关系 ID/可点击目标不变。异常字段和非法配置需报告并修复，不能用“覆写字典”掩盖。
- 若字典来自有后代覆盖的分类，旧卡片迁移应按各实际记录分类固化当时有效内容；必要时对差异子分类建立本地卡片，不能仅复制 Class 根字典导致旧显示改变。

### 9.4 r8 旧包迁移

先在旧有效配置上解析 WorkflowControl/GroupField.fieldSource 及每属性覆写，完整展开为当前实际控件；再删除所有活动关系。来源已经无效时保留旧副本和迁移报告，无法证明合法的配置不激活。

信息卡先解析 labelMode/valueMode 与其当时有效标题、格式、字典，保留已有显式改动，再转成本地内容。不能直接删字段导致名称/字典回退。旧自动跟随特性保留在只读旧契约兼容导入路径，不进入新契约编辑器和运行时。

## 10. 工作流式再编辑：可见性、资格测试与真实数据回灌

### 10.1 工作流头部两个独立开关

- “在便捷测绘中可选”：控制采集列表是否显示该工作流；关闭不等于删除工作流，也不禁用其编辑用途。旧工作流默认开启，保留原采集列表。
- “编辑用标准工作流”：控制对应分类及后代编辑时是否使用该工作流的编辑投影。整体 external 工作流本身不直接转换；它们的 Class 使用单独的原生 composed 编辑工作流。

### 10.2 开启时的阻断弹窗与测试

点击开启即显示应用统一风格的模态弹窗，阻断其他编辑操作直到测试结果出现；显示检测项、处理中、成功/失败原因，支持失败后关闭查看报告。不使用浏览器 alert/confirm 拼凑流程。

前置条件逐项检测：

1. 正好三页：填写人、信息收集、单一要素绘制；不把隐藏空页当作删除，不压缩不合格工作流来绕过条件。
2. 不包含额外绘制。
3. 只包含一个针对要素的绘制，绑定一个明确输出；有其他非绘制输出不能假装属于单记录编辑。
4. 不包含有启用条件的填入模块，包括组内条件模块；页面/输出的条件分支也不能造成编辑记录被跳过。条件必填与启用条件分开识别，但都须验证回填及保存合法性。

之后实际生成编辑投影并试验回填/输出：

- 解析输入与 assignments、geometry bindings、重复组、tags/extensions 的依赖图；保留用于普通字段或其他保留模块的所有输入。
- 仅当输入经所有依赖路径只参与 ID 组装时才移除；同时参与 Name/其他字段、条件、组装依赖的输入不能删除。未知依赖不得猜成 ID 专用。
- 直接 slot → 字段、可明确回填的组数组、classificationPicker、geometry/height 可建立标准回填。拼接、多个输入参与一个字段、不可逆计算、多个目标值不一致、默认重算覆盖记录等，需声明明确受控回填映射并实测，不能任意反解。
- 缺少回填映射时报告具体控件/目标/表达式，保持开关关闭；报告可引导配置专用编辑工作流。对保留仅用于 ID 的派生赋值进行静态清理后再校验，不能删除非 ID 数据赋值。
- 成功仅生成编辑用投影，不改采集页面顺序、输入与 ID 组装；开启标记引用规范工作流，由同一编译器生成编辑执行模型，不维护第二套脱节草稿。
- 工作流/字段/分类随后发生修改，需要使资格缓存失效，并在保存/预检时重跑；已经开启但后来不合法时阻断保存，不能带着失效资格继续运行。

r4 结构核验：16 个 composed 工作流符合上述四项结构前置条件；TPP 为四页、含辅助绘制，不符合；3 个 external 不走此转换。16 个还没有执行本轮编辑投影与回填测试，不能宣称已全部可用于再编辑。

### 10.3 编辑页面与状态机

- 对工作流所标记分类及其后代生效，精确匹配优先、再取最深祖先；同一范围存在多个编辑工作流时核验阻断，不能按数组顺序随机选一个。
- 最顶端添加 ID 的整行 text 模块，回填原 ID；移除仅参与 ID 组装的输入。编辑保存采用该 ID，不执行创建时的 ID 重算。
- 保留其余输入模块及固定 tags/extensions 单元，逐一回填已有记录；不以控件默认值覆盖 0/false/null/空字符串/空数组等真实值。
- 进入编辑即恢复原几何并开启绘制；参考 V1 现有 editingLayerId、setDrawing、drawMode、multipart 恢复、草稿替换状态，覆盖移动点、加删点、撤销重做、多部件/内环、退出/放弃、世界切换。
- 当前 NativeWorkflowHost 是创建输出 Host，没有 initialRecord/编辑提交生命周期；新增明确 edit 上下文和回填适配器，不能将原记录套进新建流程重复创建要素。
- 保存以原记录为基底，只更新本次受控字段和最新几何；保留未参与模块的未知字段、原 tags/extensions、创建人/时间，以及不能擅改的分类/World。更新编辑人/时间按现有规范。
- 若用户改 ID，按当前世界/图层范围检查冲突，并原子处理受影响索引/引用；无法安全处理时报告并阻断，不能覆盖另一要素。
- 输出必须通过同一记录校验及地图图层更新路径；编辑产生的是替换原图层，取消则完整恢复原图层，不增加重复要素/导航记录。
- world 不一致时暂停绘制，不把另一世界坐标写回。临时挂载对象、已提交测绘对象的修改去向遵守现有 V1 编辑层状态，不能直接修改 GitHub 来源数据。
- 没有适用编辑工作流时保留既有完整编辑入口；这不构成标准采集工作流退回旧 executor。

### 10.4 整体采集、原生编辑分工

- 铁路 RLE、交易点 TRP 及车站组继续使用现有整体 external 采集，不改整体输出体系。
- 为这些分类提供独立 composed 编辑工作流，便捷测绘开关默认关闭、编辑开关通过测试后开启。
- 车站整体覆盖 STA、PLF、PFB、STB、SBP、STF；编辑模板不能只覆盖 STA 就声称整个车站组已完成。按 V1 真实编辑定义逐类制作、核验，缺少可逆回填时逐项报告。
- 编辑模板只编辑当前记录，不重新运行整体采集创建关联的一组新要素；保留原有关联字段和信息卡/导航行为。

## 11. 字段高级区、信息卡覆写与重复功能清理

### 11.1 字段保持纯净，但保留数据约束

字段定义保留路径/名称 zh/en、描述、数据类型、值数量、字典、格式、必需性、继承，以及确实用于记录合法性的约束；预填只是减少重复查找，不改变字段本身的数据契约。

| 当前字段设置 | 本轮处理 |
| --- | --- |
| 控件输入提示 placeholder | 从字段区移除，归工作流/编辑控件所有 |
| 输入默认值 defaultValue | 从字段区移除；先展开到实际消费控件，数值/布尔/数组类型保留 |
| 输入执行/条件必填配置 | 输入条件归控件；真实记录的条件合法性仍由数据校验负责，不随 UI 清理消失 |
| reference 中的搜索/展示配置 | 归工作流搜索或信息卡关系设置；必要的数据引用目标/匹配约束保留于字段数据约束 |
| sourceRuntimeField/历史映射 | 不作为新增用户可选的另一套字段名；确认迁移读取/分类排除/兼容用途后再处理，不盲删 |
| scenes 用途开关 | 保留确实影响字段可用性的约束；与活动来源跟随无关，不因取消预填耦合全部删除 |

当前 r4 默认包实际有两处字段默认值：PLF Situation=true、Connect=true；两处条件必填：TPP TGTcoordinate.x/z 在 TGTWarp 为空时必需。placeholder/reference 在该默认包未设置。迁移先证明默认值已落入应有控件或整体工作流行为；保留 TPP 两分支真实记录完整性校验。用户已保存自定义包可能包含更多属性，必须扫描全部消费者，不能用默认包的零计数推断一律可删。

删除旧“默认值、提示、条件与引用”混合面板。必要数据约束集中在明确命名的“记录校验/字段引用约束”中，控件设置留在控件区域，不以后台隐藏状态继续活动跟随。

### 11.2 已确认的重复项与保留位置

| 重复/混杂项 | 当前证据 | 合并方式 |
| --- | --- | --- |
| 值规范化 / 保存值规范化 | WorkflowControlSettings 与 ControlEditor 都写 control.valueNormalization | 每个控件仅一个“保存值处理”入口，集中于控件数据设置 |
| 重复组字段必填 / 默认值 | GroupFieldEditor 上方手写一份，下方 WorkflowControlSettings 再写一份 | 删除手写副本，复用同一设置组件，保留类型正确的默认值编辑 |
| 分类创建入口 | 总区无 parent 的面板、编辑区有 parent 的面板、addChild 文本入口 | 统一到新增分类总面板 |
| 信息卡跟随 / 名称覆写 / 值覆写 / 手动覆写对照 | 多种状态与编辑入口并存 | 改一次性预填与本地名称/格式，删跟随及字典覆写入口 |
| 工作流预填 / fieldSource / 属性覆写 / 恢复跟随 / 独立配置 | fieldReuse 运行时不断解析来源关系 | 一个“预填”窗口，迁移展开后删除全部关系状态 |
| 高度槽位选择与大片通用输入编辑 | 上方选取，下方定义，外框遗漏使含义更不清楚 | 保留职责但合并呈现：高度输入选择旁编辑本地输入，基础设置可见、高级折叠；不重复列两套属性 |

“填写格式”与“保存值处理”不完全重复：前者控制链接/日期/JSON/普通文字等输入展示和合法格式，后者控制 trim/简称规范/数值转换。应明确命名和适用类型，不将二者随意合并成一个枚举；数字、布尔、JSON 等不适用的文本归一化隐藏或阻断。

全量筛查所有面板，建立配置路径 → 编辑入口清单。每个属性只允许一个主编辑入口；预览/有效来源报告允许只读重复展示，但明确“只读”。不能因位置不同就让多个控件竞争写同一属性。
